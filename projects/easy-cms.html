Easy CMS

A simpler way to update a heavy-information website, for institute staff who never learned HTML

  • For admin staff at IIT Roorkee
  • Demo AMRUT Centre website
  • Built a working prototype
Try the prototype Read the journey

Objective

At IIT Roorkee, every notice, event and faculty change on a department or centre website goes through Chakra, a CMS that accepts only HTML. The people who own those updates are admin staff, not coders. Easy CMS lets them post a correct, accessible, bilingual update by filling a familiar form, and lets a faculty reviewer approve it from a true preview before anything goes public.

  • True live preview
  • Review and approval loop

The editor, step by step

Posting an announcement from a message that arrived on WhatsApp.

1Home

What do you want to update?

Five task cards in the users’ own words, the most used first. Anything sent back waits on the right.

  • Status in words, colour and icon
  • Website health from GIGW checks

2Helper

Paste the message

Most updates already exist as an email or a WhatsApp forward. The editor pastes it instead of retyping.

The helper only copies dates, names and links from the text. It never invents them and never posts anything.

3Helper

Every filled field is marked

Each filled field gets a dashed amber outline and a Looks right button. The preview beside it is the real page.

  • Amber means suggested, not settled
  • One click to confirm or clear

4Check

It will not send unconfirmed work

Sending runs the check first. Must-fix items block it; notes like a missing Hindi title can be sent anyway.

  • Plain words, no blame
  • Go there jumps to the field

Must-fix items block sending. The reviewer sees the same notes.

5Hindi

Make Hindi version

One press drafts the Hindi title. It stays labelled Machine translated until a person ticks I checked it.

  • GIGW asks for both languages
  • The label travels to the reviewer

6Send

Send to the Coordinator for checking

The button names the person. A short dialog lists any notes.

7My updates

Where everything stands

Drafts, sent back, waiting, live and expiring soon. Search by any word in the title.

  • Hindi version shown per row
  • Owner and last change on every item

What changed, the notes the editor saw, and the page as readers will see it. One tap approves; one line sends it back.

The preview is the real page

Preview and public site are drawn by the same components from the same data. The centre’s site was redesigned too: blue, purple accents, orange only for alerts.

Form and preview are two tabs on a phone.

Help and an assistant, in the same place

Both sit top right on every screen. Help shows where things are; the assistant answers from the website itself.

?Help

Show me, not tell me

Asked “how do I add a poster?”, help answers in steps and outlines the Poster field.

  • Same place on every screen
  • Answers point at real controls

AIAssistant

An assistant that reads before it speaks

It wears glasses because its job is to read carefully: what was sent back, what leaves the site this week, what fails a GIGW check. Paste a message and it drafts a notice, then hands it to the form for a person to confirm.

  • Answers come from the website’s own data
  • Drafts open in the form, never straight to review
  • Amber, like every other suggestion

It only suggests. A person checks every field, and the Coordinator approves before anything goes live.

Accessibility and GIGW

The interface aims for WCAG 2.1 AA; what it publishes is GIGW-ready by default.

हिन्दी. The whole interface, help included.

Dark. Deep navy; status colours keep their meaning.

  • Picture descriptions required
  • Hindi status on every item
  • Removal dates, auto archive
  • Scanned PDFs flagged
  • Vague and broken links flagged
  • Owner and date on every page
  • Keyboard throughout
  • High contrast and dark
  • Text size that reflows
  • 44 px touch targets
  • Reduced motion
  • Never colour alone
